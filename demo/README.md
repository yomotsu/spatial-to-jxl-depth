# JPEG XL Depth Parallax Demo

公開デモ: https://yomotsu.github.io/spatial-to-jxl-depth/

初期画面には画像を含めず、ドロップゾーンだけを表示します。クリックまたはドロップした画像はブラウザ内で読み込み、サーバーへ送信しません。サンプル画像や写真は同梱していません。

## 起動

`demo/` を静的ファイルとして配信し、ブラウザで開きます。例:

```sh
cd demo
python3 -m http.server 8000
```

`http://localhost:8000` を開きます。静的サーバーで動作し、API や変換サーバーには接続しません。

JPEG XL の色画像は `createImageBitmap()` によるブラウザ標準デコードを優先し、非対応ブラウザでは同梱の WebAssembly デコーダーにフォールバックします。深度などの追加チャンネルはブラウザ標準の画像APIから取得できないため、同梱の JavaScript デコーダーで抽出します。その他の形式はブラウザが画像として読み込める場合に表示できます。ファイルは端末内で処理し、アップロードしません。

色画像と深度は同時に読み込み、JavaScript による深度抽出と WebAssembly による色のデコードは独立した Web Worker で並列実行します。ワーカーとデコーダーは再利用し、デコード後の画素バッファーは所有権を転送してコピーを避けます。ファイル選択やドラッグ開始時にワーカーを準備し、外部の深度マップを指定した場合は内蔵深度の抽出を省略します。ワーカーを起動できない環境ではメインスレッドで処理します。

深度チャンネル型を持つ JXL は、1枚を読み込むだけで深度を抽出して視差に使います。深度チャンネルの値は 0〜1 に正規化し、値が小さい遠景ほど大きく動かします。現在は符号なし整数の深度チャンネルに対応します。深度チャンネルがない JXL や他の画像形式では、色画像とグレースケール深度マップを同時に選んでください。ファイル名に `depth` または `disparity` が含まれる画像を深度マップとして扱います。2枚の名前で判別できない場合は、1枚目を色画像、2枚目を深度マップとして読み込みます。

高解像度 JXL の深度抽出はブラウザのメモリーを多く使うことがあります。抽出に失敗した場合も色画像は表示し、深度が使えない理由を画面に表示します。

視差で隙間が開く側には、移動量に合わせて滑らかにした深度を使い、輪郭付近の引き伸ばしを周囲に分散させます。背後に隠れる側には元の深度を使い、手前の物体でクリップします。色画像にはぼかしをかけません。「深度マップを見る」では元の深度を表示します。画像の端が筋状に伸びないよう、視差の強さに応じて表示範囲を少し拡大します。視差を 0 にすると画像全体を表示します。

設定の「描画方式」で、「深度メッシュ（3D）」と「深度ワープ（2D）」を切り替えられます。初期値は深度メッシュです。画像を読み直す必要はなく、視差の強さ・マウス操作・端末の傾きは共通です。「深度マップを見る」は両方式で使え、色画像に戻すと選択中の方式に戻ります。深度のない画像では方式の選択を無効にします。

3Dメッシュは元の深度から細かな三角形の面を作り、写真を参照視点から投影します。視点移動時は深度テストで背後を隠します。境界の三角形をつないでいるため、隙間が開く側には引き伸ばしが発生します。写っていない背景の生成や補完は行いません。メッシュは最初に選択したときに作成し、画像の差し替え時に破棄します。WebGL 1 で動作し、外部ライブラリーは使用しません。

`vendor/jxl/` には `@jsquash/jxl` 1.3.0 のブラウザ用デコーダーを含みます。ライセンスは同ディレクトリ内の `LICENSE` を参照してください。

`vendor/jxl-depth/` には PureJsImage の JPEG XL 追加チャンネル抽出処理を含みます。ライセンスは同ディレクトリ内の `LICENSE` を参照してください。写真、HEIC、JXL ファイルはリポジトリに含めていません。
